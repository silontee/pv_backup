# Plan v8: Data-Model 정합형 실행계획

> 기준일: 2026-04-22
> 데이터 단일 기준 문서(SSoT): `plan/main/data_strategy.md`
> 모델 설계 단일 기준 문서: `pv/pv_predict.md`

## 1. 목적 요약

- V8은 전략 문서가 아니라 즉시 실행 가능한 운영 계획이다.
- 데이터 현황, EDA, 모델링, 검증을 하나의 의사결정 체인으로 고정한다.
- 모델 전략은 `Hybrid 2-Track`으로 확정한다.
  - Track A: LightGBM 계열 기준선으로 빠른 성능 하한 확보
  - Track B: Bayesian 계층 모델로 불확실성/일반화/리스크 해석 확보

## 2. V7 대비 핵심 변경사항

### 2.1 데이터 현황 갱신

- PV 유효 학습 유닛을 `11`로 고정한다.
- GHI는 `GK-2A + DQF 재정의 + 재수집(retry)` 흐름을 기준 운영안으로 반영한다.
- 결측 이슈를 단순 누락이 아니라 아래 문제로 재정의한다.
  - `DQF 클래스별 편향`
  - `시간대별 누락 패턴`
  - `편향이 모델 오차 구조로 전이되는 리스크`

### 2.2 EDA 목적 전환

- 기존: 상관 확인 중심
- 변경: `GHI ↔ 발전량 정보차`를 정량화하는 검증형 EDA
  - 시간 정렬 정확도
  - 품질 조건(DQF) 민감도
  - 사이트 간 이질성
  - 학습 가능성 등급(A/B/C)

### 2.3 모델 연결성 명문화

- 데이터 이슈와 모델 선택 이유를 1:1로 연결한다.
- 불균형/저표본 사이트 문제에는 계층(Partial Pooling)으로 대응한다.
- 품질 불확실성/대체 오차는 베이지안 예측구간으로 전달한다.

## 3. Data Contract (학습 입력 계약)

학습 단위를 `site-hour`로 통일한다.

### 3.1 필수 키

- `site`
- `unit`
- `site_unit`
- `site_cluster`
- `datetime_kst`

### 3.2 필수 입력 컬럼

- 복사 표기: `ghi`, `temp_c`, `rh`, `wind_ms`
- 품질 표기: `quality_mask`, `dqf_class`, `source_flag`
- 시계열 표기: `hour`, `month`, `doy`, `lag_*`, `rolling_*`
- 외생/예보 표기(가능 시): `weather_*`

### 3.3 타깃

- 기본 타깃: `gen_kwh_hourly`
- 병행 타깃(선택): `gen_kw_norm = gen_kwh_hourly / capacity_kw`

### 3.4 계약 위반 처리

- 필수 컬럼 누락 배치는 학습 투입 금지
- 시간 인덱스 불연속/중복은 사전 정합 단계에서 차단
- `quality_mask=0` 구간은 학습 제외 또는 감쇠 가중치 적용(실험 로그 의무)

### 3.5 `site_cluster` 규칙 (고정)

- Track B의 상위 계층 단위는 권역명이 아니라 `site_cluster`로 고정한다.
- `site_cluster`는 Stage B 결과(반응 곡선/분산 구조/lag 특성) 기반으로 생성한다.
- 최소 조건:
  - 각 cluster는 2개 이상 site를 포함(단독 cluster는 예외 사유 기록)
  - cluster별 샘플 수 편차가 과도할 경우 병합 또는 가중치 보정
  - 재수집 후 cluster 재산정 여부를 로그로 남김

## 4. EDA V3 실행 순서 (고정)

## Stage A. Time Integrity Gate

1. 타임존, 리샘플 규칙, 시간 인덱스 연속성 검증
2. 중복/결측/비정상치 분해
3. 사이트별 `valid_rate`, `missing_rate`, `duplicate_rate` 산출

Go 기준:

- 시간 인덱스 규칙 위반 0건
- 중복 레코드 처리 규칙 문서화 완료

## Stage B. Information Gap Diagnosis

1. GHI-발전량 관계의 lag 구조 분석(0~6h 기본)
2. 비선형 반응(시간대/계절 분리) 확인
3. 사이트별 분산 분해(공통/사이트 고유)

Go 기준:

- 유효 사이트별 핵심 lag와 반응 구간 정의 완료
- 공통 구조와 사이트 특이 구조 분리 가능

## Stage C. Quality Sensitivity

1. DQF 클래스별 분포/성능 차이 비교
2. DQF 재수집 전후 분포 드리프트 비교
3. `quality_mask` 정책 후보(제외/감쇠/보정) 결정

Go 기준:

- DQF 정책 1안 확정
- 정책별 성능/커버리지 영향 확인

## Stage D. Trainability Grading

1. 유닛별 유효 샘플 수/품질 비율/계절 커버리지 산정
2. A/B/C 등급 부여
3. 모델 투입 범위 확정

등급 기본안:

- A: 즉시 학습 가능
- B: 제한 학습(가중치/보조규칙 필요)
- C: 학습 제외(재수집 대기)

## 5. 모델 로드맵 (Hybrid 2-Track)

## Track A: Baseline (단기)

- 모델: LightGBM 계열
- 목적:
  - 빠른 기준 성능 확보
  - 피처 유효성 점검
  - 홀드아웃 하한선 설정
- 산출물:
  - 기준 성능표
  - 상위 피처 목록
  - 사이트별 오차 히트맵

## Track B: Bayesian Hierarchical (중기 메인)

- 모델: `site_cluster → site → time` 계층 + 불확실성 추정
- 목적:
  - 사이트 불균형 대응(Partial Pooling)
  - 저데이터 사이트 일반화
  - 예측구간 기반 리스크 전달
- 산출물:
  - posterior 기반 성능/캘리브레이션
  - 구간 커버리지 리포트
  - 사이트별 불확실성 프로파일

## 채택 규칙 (Track 결합)

- Track A가 최소 성능 하한을 충족해야 Track B 비교 가능
- Track B 채택은 아래 3개 중 2개 이상 충족 시 승인
  - 캘리브레이션 개선
  - 예측구간 커버리지 개선
  - 저데이터 사이트 안정성 개선

## 6. 베이지안/계층 채택 이유 (명문화)

1. 표본 불균형과 사이트 이질성에서 과적합을 줄이기 위해 계층 구조가 필요하다.
2. DQF/결측 대체로 인한 관측 불확실성을 점추정이 아닌 분포로 전달해야 한다.
3. 운영 의사결정은 점예측 단독보다 신뢰구간/시나리오가 중요하다.
4. 데이터 재수집이 반복되는 환경에서 사후분포 기반 업데이트가 유지보수에 유리하다.

## 7. 운영 문서화 규칙

`plan_v8`의 모든 상태 표기는 다음 두 영역으로 분리한다.

- `현재 확정 사실 (as-is, 2026-04-22 기준)`
- `재수집 후 재검증 항목 (to-verify)`

재수집 이후 자동 재평가 체크리스트를 고정한다.

1. Time Integrity Gate 재실행
2. DQF 분포 재집계
3. A/B/C 등급 재산정
4. Track A 재학습 트리거
5. Track B posterior 업데이트 트리거
6. 버전 비교표 자동 생성

## 8. Test Plan / Acceptance Criteria

## 데이터 무결성

- 시간 인덱스 연속성, 중복률, 결측률, DQF 분포가 임계치 내
- 사이트별 최소 유효 샘플 기준 충족

## EDA 산출물

- 사이트별 정보차 리포트(상관/lag/분산분해) 생성
- DQF 클래스별 민감도 표 생성

## 모델 검증

- 기준선: 홀드아웃 최소 하한 충족
- 베이지안: 캘리브레이션 + 커버리지 기준 충족
- 저데이터 사이트: 기준선 대비 안정성 개선 확인

## 운영 검증

- 재수집 후 동일 파이프라인 재실행 시 재현성 확보
- 데이터 버전별 결과 비교표 자동 생성

## 9. 실행 우선순위 (2주 기준)

### Week 1

- Data Contract 고정
- Stage A/B 완료
- Track A 1차 학습

### Week 2

- Stage C/D 완료
- Track B 1차 학습
- 채택 규칙 기반 비교 리포트 작성

## 10. 가정 및 기본값

- 최신 사실의 1차 기준은 `plan/main/data_strategy.md`로 고정한다.
- 모델 논리의 1차 기준은 `pv/pv_predict.md`로 고정한다.
- 현재는 재수집 재실행 전 단계이므로, 본 계획은 `현 상태 실행안 + 재수집 후 재검증 게이트`의 2단 구조로 운영한다.
- 단기 목표는 최고 성능보다 `정합성 확보 + 리스크 가시화 + 모델 선택 근거 확보`를 우선한다.
